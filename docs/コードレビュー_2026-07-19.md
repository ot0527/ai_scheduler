# コードレビュー & リファクタリング報告(2026-07-19)

全体評価: 設計は良好。レイヤー分離(core / web / Edge Functions)が守られ、RLS 全14テーブル有効、AI 出力の Zod 検証・承認フローも仕様どおり。テスト 32→36 件、型チェック・ビルドすべてパス。

## 修正済み(コミット前に diff 確認推奨)

### バグ修正

1. **`core/scheduling/validation.ts` — 日跨ぎ就寝の誤検出**
   `calculateFreeTime` は就寝≦起床のとき終端を +1440 分するが、`validatePlacedBlocks` は正規化せず比較していた。就寝 00:30 の設定では 23:30 以降の配置がすべて `out_of_bounds` 誤判定 → スケジュール生成が「衝突があります」で失敗する。正規化を追加し、回帰テスト `tests/validation.test.ts` を新設。

2. **`functions/_shared/schedule-utils.ts` — 小規模リスケの作業消失**
   元ブロックを先に `rescheduled` 化してから再配置先を保存していたため、再配置先の日が承認済みでスキップされると、その作業が両方から消えていた。保存に成功した placement のみ `rescheduled` 化し、スキップ分は `unplaced` として返すよう修正。

3. **`functions/_shared/schedule-utils.ts` — アラート全消し**
   週次不足アラート作成時に未読アラートを全削除していた。`goal_id IS NULL` の週次アラートのみ入れ替えるよう限定。

### セキュリティ改善

4. **`functions/_shared/call-ai.ts`** — Gemini API キーを URL クエリから `x-goog-api-key` ヘッダーへ移動(アクセスログへの漏洩防止)。
5. **`functions/_shared/cors.ts`** — 不許可オリジンに `allowed[0]` を返すフォールバックを削除(ヘッダー無しで拒否)。`Access-Control-Allow-Methods` と `Vary: Origin` を追加。

### リファクタリング(重複排除・可読性)

6. **日付キー関数の統一** — `toDateKey`(core)/ `toLocalDateKey`(useBudgets)/ `todayDateString`(utils)が同一実装で3重定義。core の `toDateKey` へ委譲し、残り2つは `@deprecated` の互換エイリアスに。
7. **時間表示関数の統一** — `formatMinutesLabel`(mappers/goal)と `formatDuration`(formatters)が同一実装。前者を後者への re-export に。
8. **`overrides.ts`** — `resolveLifeRoutineForDay` の3重オブジェクトリテラルを base + spread に集約。
9. **`scoring.ts`** — 未使用変数 `slotStartTime` を削除。
10. **`placement.ts`** — 候補ループ内の `templates.find`(O(n²))を Map 化。
11. **`pnpm-lock.yaml`** — package.json と不整合(削除済み date-fns が残存)だったため再生成。`--frozen-lockfile` が通る状態に。

## 第2弾修正(同日追加対応)

12. **アトミック加算の RPC 化** — 新規マイグレーション `20260719000000_atomic_ops.sql` に `increment_tokens_used`(service_role 専用)・`increment_goal_progress`・`increment_budget_progress`(SECURITY INVOKER、RLS で本人の行のみ)を追加。`ai-utils.ts recordTokenUsage` と `useExecution.ts` の read-modify-write を単一 UPDATE に置換し、並行リクエストでの加算消失を解消。
13. **`goal-approve-decompose` のトランザクション化** — 同マイグレーションの `approve_goal_decompose(p_goal_id, p_payload)` RPC に削除→挿入→更新を集約。途中失敗時は全ロールバック。Edge Function は Zod 検証後に RPC を呼ぶだけに簡素化。
14. **固定予定の日跨ぎ対応** — `block-builders.ts` で endTime ≦ startTime を翌日側へ延長(夜勤等)。テスト追加。
15. **`budget.ts` の端数按分** — floor 切り捨てで余る分を、小数部の大きい目標から順に配分(必要時間は超えない)。合計が利用可能時間に一致することをテストで保証。
16. **`placement.ts` の複数ブロック配置** — 「1スロット1ブロック」制約を撤廃し、スロット内カーソル方式で長い空き時間に複数ブロックを連続配置(ユーザー承認済みの挙動変更)。テスト追加。
17. **`call-ai.ts` のエラー判定** — 日本語メッセージの文字列マッチを廃止し、`retriable` フラグ付き `AIError` クラスへ。
18. **OpenAI `max_tokens` → `max_completion_tokens`** — 非推奨パラメータを現行推奨形へ移行(全モデル互換・o系で必須)。
19. **`.gitattributes` 追加** — `* text=auto eol=lf` で改行コードを統一。既存ファイルへ適用するにはコミット後に `git add --renormalize .` の実行が必要。
20. **`database-types.ts`** — 新 RPC 4件の型定義を `Functions` に追加(web の型付きクライアント用)。

## 未修正の指摘(軽微・要判断)

- **`scheduled_blocks` の `start_time < end_time` 制約** — 日跨ぎ就寝で 24:00 以降に配置されたブロックは TIME 型変換で制約違反になりうる。日跨ぎ配置を本格運用するなら target_date + タイムスタンプ化の検討を。
- **`ai-chat` などが AI エラーメッセージをそのままクライアントへ返す**(502)— 現状メッセージはユーザー向け日本語のため実害小。
- **`delete-account`** — Vault キー削除失敗時もアカウント削除を続行(ログのみ)。孤児シークレットが残る可能性。
