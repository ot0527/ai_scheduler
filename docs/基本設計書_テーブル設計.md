## 生活基盤関連

### profiles（プロフィール）

profiles テーブルでは、ユーザーの表示名とタイムゾーンを保持する。
認証ユーザー作成時に自動で 1 行生成される。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 認証ユーザー ID と 1 対 1 |
| `name` | TEXT | 表示名 |
| `timezone` | TEXT | タイムゾーン（既定: `Asia/Tokyo`） |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

---

### user_preferences（基本設定）

user_preferences テーブルでは、スケジュール計算の前提条件を保持する。
ユーザー 1 人につき 1 行。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID（一意） |
| `wake_time_weekday` | TIME | 平日の起床時刻 |
| `wake_time_weekend` | TIME | 休日の起床時刻 |
| `sleep_time_weekday` | TIME | 平日の就寝時刻 |
| `sleep_time_weekend` | TIME | 休日の就寝時刻 |
| `max_session_minutes` | INTEGER | 1 回あたりの作業可能時間（分） |
| `focus_times` | TEXT[] | 集中しやすい時間帯 |
| `break_frequency_minutes` | INTEGER | 休憩の頻度（UI 未使用） |
| `break_duration_minutes` | INTEGER | 休憩の長さ（UI 未使用） |
| `notification_settings` | JSONB | 通知プライバシー設定（後述） |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

初回設定完了の判定は、平日の起床・就寝時刻が両方設定されていること。

**notification_settings（JSONB）**

| キー | 説明 |
| --- | --- |
| `showDetailedAlerts` | アラート詳細の表示可否 |
| `enablePushNotifications` | Web Push 有効化フラグ（将来対応） |

**主な画面**: 初回設定、基本設定、通知設定

---

### life_routines（生活リズム）

life_routines テーブルでは、食事・風呂などの定例生活イベントを保持する。
ユーザー入力により、以下の項目を設定する。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID |
| `type` | ENUM | 種類（朝食/昼食/夕食/風呂/休憩/その他） |
| `label` | TEXT | 表示ラベル（任意） |
| `preferred_time` | TIME | 希望時刻（「ごろ」の中心） |
| `earliest_time` | TIME | 最早許容時刻 |
| `latest_time` | TIME | 最遅許容時刻 |
| `duration_minutes` | INTEGER | 所要時間（分） |
| `flexibility` | ENUM | 固定 / 柔軟 |
| `applies_to` | ENUM | 平日 / 休日 / 毎日 |
| `sort_order` | INTEGER | 表示順 |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

希望時刻入力時、許容幅（既定 ±30 分）から最早・最遅時刻を自動算出して保存する。

**主な画面**: 生活リズム

---

### fixed_schedules（固定予定）

fixed_schedules テーブルでは、原則動かせない曜日固定の予定を保持する。
空き時間計算から除外される。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID |
| `title` | TEXT | 予定タイトル |
| `start_time` | TIME | 開始時刻 |
| `end_time` | TIME | 終了時刻 |
| `days_of_week` | INTEGER[] | 曜日（0=日 … 6=土） |
| `commute_minutes` | INTEGER | 移動時間（分） |
| `is_editable` | BOOLEAN | 編集可能フラグ |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

**主な画面**: 固定予定

---

### routine_day_overrides（当日変更）

routine_day_overrides テーブルでは、特定日の起床・就寝・生活リズムの上書きを保持する。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID |
| `target_date` | DATE | 適用日 |
| `target_type` | ENUM | 起床 / 就寝 / 生活リズム |
| `life_routine_id` | UUID | 対象の生活リズム ID（生活リズム変更時） |
| `action` | ENUM | 時間変更 / スキップ |
| `preferred_time` | TIME | 変更後の時刻 |
| `earliest_time` | TIME | 最早許容時刻 |
| `latest_time` | TIME | 最遅許容時刻 |
| `duration_minutes` | INTEGER | 所要時間（生活リズム変更時） |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

就寝の当日変更は `user_preferences` ではなく、本テーブルの `target_type = sleep` で保持する。
同一日・同一対象は 1 行のみ（一意制約）。

**主な画面**: ホーム（当日変更）

## 目標管理関連

### goals（目標）

goals テーブルでは、ユーザーが登録する長期目標を保持する。
目標登録時は下書き状態とし、AI 分解承認後に有効化する。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID |
| `title` | TEXT | 目標名 |
| `category` | ENUM | カテゴリ（学習/創作/運動/仕事 等） |
| `deadline` | DATE | 達成期限 |
| `current_status` | TEXT | 現状の記述 |
| `target_condition` | TEXT | 達成条件 |
| `priority` | ENUM | 優先度（高/中/低） |
| `weekly_available_minutes` | INTEGER | 週あたりの利用可能時間（分） |
| `avoid_time_slots` | TEXT[] | 避けたい時間帯 |
| `estimated_total_minutes` | INTEGER | AI 推定の総所要時間 |
| `completed_minutes` | INTEGER | 完了済み時間 |
| `feasibility` | ENUM | AI 判定の達成可能性 |
| `ai_summary` | TEXT | AI 要約 |
| `status` | ENUM | 下書き / 有効 / 完了 / アーカイブ |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

**主な画面**: 目標一覧、目標登録、目標詳細

---

## AI 支援関連

### user_ai_settings（AI 設定）

user_ai_settings テーブルでは、AI プロバイダの設定を保持する。
ユーザー 1 人につき 1 行。API キー本体は Vault に保存し、本テーブルには参照情報のみ保持する。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID（一意） |
| `provider` | ENUM | OpenAI / Gemini |
| `model` | TEXT | モデル名 |
| `api_key_ref` | TEXT | Vault 内キー参照 |
| `api_key_last4` | TEXT | キー末尾 4 桁（表示用） |
| `monthly_token_limit` | INTEGER | 月間トークン上限 |
| `tokens_used_this_month` | INTEGER | 当月使用量 |
| `usage_reset_at` | TIMESTAMPTZ | 使用量リセット基準 |
| `ai_tone` | TEXT | 口調（丁寧/カジュアル/簡潔） |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

**主な画面**: AI 設定

---

### ai_request_logs（AI 呼び出しログ）

ai_request_logs テーブルでは、AI 呼び出しの監査ログを保持する。
入力・出力はマスキング済み要約のみ保存する。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID |
| `request_type` | ENUM | 種別（分解/リスケ/相談/接続テスト） |
| `input_summary_masked` | TEXT | マスキング済み入力要約 |
| `output_summary_masked` | TEXT | マスキング済み出力要約 |
| `provider` | ENUM | 使用プロバイダ |
| `token_usage` | JSONB | トークン使用量 |
| `created_at` | TIMESTAMPTZ | 作成日時 |

90 日超のログは定期削除 RPC で削除する（cron 未設定）。

### goal_budgets（週次時間予算）

goal_budgets テーブルでは、目標ごとの週次時間予算を保持する。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | UUID | 主キー |
| `user_id` | UUID | ユーザー ID |
| `goal_id` | UUID | 目標 ID |
| `period_start` | DATE | 週開始日（月曜） |
| `period_end` | DATE | 週終了日（日曜） |
| `required_minutes` | INTEGER | 必要時間 |
| `allocated_minutes` | INTEGER | 割当時間 |
| `completed_minutes` | INTEGER | 週内完了時間 |
| `status` | ENUM | 順調 / 遅れ / 危険 / 超過 |
| `warning_message` | TEXT | 警告メッセージ |
| `created_at` | TIMESTAMPTZ | 作成日時 |
| `updated_at` | TIMESTAMPTZ | 更新日時 |

**主な画面**: 時間予算

## 画面とテーブルの対応

| 画面操作 | 書き込むテーブル |
| --- | --- |
| 初回設定・基本設定 | `user_preferences` |
| 生活リズム CRUD | `life_routines` |
| 固定予定 CRUD | `fixed_schedules` |
| 当日変更 | `routine_day_overrides` |
| 目標登録・編集 | `goals` |
| AI 分解承認 | `goals`, `goal_components`, `work_block_templates` |
| AI 設定 | `user_ai_settings` |
| 予算再計算 | `goal_budgets`, `alerts` |
| 日次スケジュール生成 | `schedules`, `scheduled_blocks` |
| スケジュール承認 | `schedules` |
| 完了記録 | `scheduled_blocks`, `goals`, `goal_budgets` |
| 振り返り | `schedules` |
| 通知設定 | `user_preferences.notification_settings` |

## アクセス制御

全 public テーブルで Row Level Security（RLS）を有効化する。
原則として、ログインユーザー自身の行のみ読み書き可能とする。

API キーは `user_ai_settings.api_key_ref` 経由で Vault を参照し、テーブルには生キーを保存しない。
