## 7. Phase 2 で実装済みの機能

### 目標管理

- 目標 CRUD（`/goals`, `/goals/new`, `/goals/:id`）
- ステータス: `draft` → AI 分解承認後 `active`

### AI 目標分解（承認制）

1. **AIで分解する** — Edge Function `goal-decompose`（DB 未保存のプレビュー）
2. ユーザー確認
3. **この内容で作成** — Edge Function `goal-approve-decompose` → `goal_components` / `work_block_templates` 保存

**AI 呼び出し（`call-ai.ts`）**

- OpenAI / Gemini とも `maxOutputTokens: 8192`（`AI_LIMITS.goalDecomposeMaxOutputTokens`）
- Gemini の `MAX_TOKENS` または JSON パース失敗時、1 回自動リトライ
- プロンプトで出力サイズを抑制（summary 300 文字、components 12、workBlocks 24）

**Gemini で分解が失敗する場合**

- エラー「invalid JSON」「途中で切れ」→ 再試行ボタン、またはモデルを `gemini-2.0-flash` / OpenAI へ変更
- 429/403 → 無料枠上限。DB は変更されない
- **承認前に `estimatedTotalMinutes` 等を必ず目視確認**

### AI 設定（BYOK）

- `/settings/ai` — プロバイダ（OpenAI / Gemini）、モデル、API キー
- 接続テスト後 Vault 暗号化保存（`store_user_api_key` RPC）
- キーはクライアントに再表示しない（下4桁のみ）

### モデル選択肢（2026-05-24 時点）

| プロバイダ | 選択肢 | デフォルト |
| ---------- | ------ | ---------- |
| OpenAI | `gpt-4o-mini`, `gpt-4o`, `gpt-4.1-mini` | `gpt-4o-mini` |
| Gemini | `gemini-3.5-flash`, `gemini-2.0-flash`, `gemini-1.5-pro` | `gemini-3.5-flash` |

### レート制限

- 目標分解: **5 回/日**（`ai_request_logs` でカウント）
- 大規模リスケ: **3 回/日**（`request_type = 'reschedule'`）
- 月間トークン上限: UI・DB 項目あり。**超過ブロック・使用量加算は未実装**

## 8. Phase 3 で実装済みの機能

### 週次時間予算

- Edge Function `budget-calculate` — アクティブ目標から週あたり必要時間を算出し、今週の空き時間合計と比較して按分
- 不足時は `alerts` に警告 + 改善案を保存
- UI: `/budget` — 目標別の必要/割当/ステータス表示、「予算を再計算」ボタン

### 日次スケジュール生成（非 AI）

- Edge Function `schedule-generate` — 空き時間 + 作業ブロック + 週次予算をもとにスコアリング貪欲法で仮配置
- `schedules`（draft）+ `scheduled_blocks` として保存
- 固定予定衝突・起床就寝範囲外は `validation.ts` で拒否

### 承認フロー

- UI: `/schedule/approve` — 仮スケジュール確認、「再提案」「今日の予定に反映」
- 承認はクライアントから `schedules.status` を `draft` → `approved` に更新（RLS 保護）
- ホーム（`/`）— 承認済みブロック表示、draft がある場合は承認画面へ誘導

### 想定フロー

Phase 1〜4 通しのフローは §9 を参照。

```text
1. 目標を active にする（Phase 2）
2. /budget で「予算を再計算」
3. /schedule/approve で「今日の予定を生成」→ 内容確認 → 承認
4. ホームで承認済み予定を確認
```

### Phase 3 で意図的に簡略化した点

- カレンダーライブラリ（FullCalendar / schedule-x）は未導入。リスト UI のみ
- `user_choice` ブロックのメニュー選択 UI は未実装（タイトルのみ配置）

## 9. Phase 4 で実装済みの機能

### 完了記録

- UI: `/review` — 各作業ブロックを **完了 / 一部達成 / 未達成** で記録
- `scheduled_blocks.status`（`done` / `partial` / `skipped`）と `actual_minutes` を更新
- 進捗連動: `goals.completed_minutes`、今週の `goal_budgets.completed_minutes` に差分加算
- 全ブロック記録済み → `schedules.status` を `completed`、一部記録 → `in_progress`

### 振り返り

- 疲労度（1〜5）とメモを `schedules` に保存（`fatigue_level` / `review_note` / `reviewed_at`）
- **疲労度**は翌日の `schedule-generate` スコアリングに反映（前日の `fatigue_level` を参照）
  - 疲れ（4〜5）→ 軽い作業（`energy: low`）が選ばれやすい
  - 元気（1〜2）→ 負荷の高い作業が選ばれやすい
- **メモ**は DB 保存のみ（再表示・AI 連携は未実装）

### 小規模リスケ（非 AI）

- Edge Function `schedule-reschedule-minor` — 未完了ブロックを翌日〜7日後の空き時間へ draft 再配置
- 元ブロックは `rescheduled` に更新
- UI: `/review` の「未完了を再配置する」→ 再配置先の `/schedule/approve?date=...` へ誘導

### 大規模リスケ（AI）

- Edge Function `reschedule-major` — 遅延目標を要約し、週次予算の調整案を JSON で返却（**プレビューのみ**）
- ユーザー承認後、クライアントから `goal_budgets.allocated_minutes` を更新 + `alerts` に提案を保存
- レート制限: **3 回/日**（`ai_request_logs.request_type = 'reschedule'`）
- BYOK 必須（`goal-decompose` と同様）

### 承認済み予定のキャンセル

- UI: `/schedule/approve` — 「キャンセル」で `schedules.status` → `cancelled`
- キャンセル後に「再提案」で draft 再生成可能（従来は承認済みがあると生成エラー）

### スコアリング実績連動

- `scoring.ts` — `ScoringExecutionContext`（疲労度・直近完了テンプレート ID）を配置スコアに反映
- `schedule-generate` 実行時、`_shared/schedule-utils.ts` が前日疲労度・直近14日の完了ブロックを取得

### 想定フロー（Phase 1〜4 通し）

```text
1. 目標を active にする（Phase 2）
2. /budget で「予算を再計算」（Phase 3）
3. /schedule/approve で「今日の予定を生成」→ 承認（Phase 3）
4. 実行後 /review で完了記録・振り返り（Phase 4）
5. 未完了があれば小規模リスケ → 再配置 draft を承認（Phase 4）
6. 大幅遅延時は大規模リスケ（AI）→ 週次予算を承認反映（Phase 4）
```

### Phase 4 で意図的に簡略化した点

- 振り返りメモの再表示・履歴一覧 UI なし
- 大規模リスケは `goal_budgets.allocated_minutes` の更新のみ（GoalComponent 等は変更しない）
- `user_choice` ブロックのメニュー選択 UI は未実装

## 13. Edge Functions

| 関数 | 役割 |
| ---- | ---- |
| `goal-decompose` | 目標を AI 分解 → 正規化 → Zod 検証 → プレビュー返却 |
| `goal-approve-decompose` | 承認内容を再検証 → DB 保存 → `active` |
| `ai-settings` | GET: 設定状態 / POST: 接続テスト + Vault 保存 |
| `budget-calculate` | 週次時間予算計算 → `goal_budgets` upsert + アラート |
| `schedule-generate` | 日次仮スケジュール生成 → `schedules` / `scheduled_blocks` 保存 |
| `schedule-reschedule-minor` | 未完了ブロックの小規模リスケ（非 AI）→ draft 再配置 |
| `reschedule-major` | 大規模リスケ AI プレビュー（週次予算調整案） |

**デプロイ前に必須:**

```bash
pnpm --filter @ai-scheduler/core build   # dist を最新化
supabase db push                         # 未適用マイグレーションがある場合
supabase functions deploy goal-decompose
supabase functions deploy goal-approve-decompose
supabase functions deploy ai-settings
supabase functions deploy budget-calculate
supabase functions deploy schedule-generate
supabase functions deploy schedule-reschedule-minor
supabase functions deploy reschedule-major
```

**import ルール（重要）**

| 関数種別 | dist の import 方法 | deno.json |
| -------- | ------------------- | --------- |
| AI 系（`goal-decompose`, `reschedule-major` 等） | `dist/ai/*`, `dist/schemas/*` 等（`index.js` 可） | **必須**（`zod` → `npm:zod@3.25.67`） |
| 非 AI（`budget-calculate`, `schedule-generate`, `schedule-reschedule-minor`） | **`dist/index.js` 禁止**。`dist/scheduling/*.js`, `dist/mappers/*.js` を直接 import | 不要 |

`_shared/schedule-utils.ts` は上記非 AI ルールに従う。`dist/index.js` は zod 付き schemas / ai を再 export するため、Deno が `zod` 解決エラーになる。

## 16. 既知の技術的判断・注意点

### Phase 1 由来（変更なし）

- `database-types.ts` は手動管理（`supabase gen types` 出力を反映）
- 「ごろ」は対称 ±30 分
- 当日変更 skip は空き時間計算未反映
- `target_date` はブラウザローカル日付（SQL Editor の UTC とずれる）
- 固定予定 `commute_minutes` は終了時刻の後のみ

### Phase 2 追加

- AI 分解の正規化デフォルト — **承認前に内容を必ず目視確認**
- Gemini 無料枠上限 — 429/403 で分解失敗
- Gemini 出力途切れ — 大きな目標で JSON 不完全になることがある（`maxOutputTokens` + リトライで緩和。それでも失敗時はモデル変更を検討）
- 月間トークン上限は現状ブロックしない

### Phase 3 追加

- 週次空き時間計算は当日変更を含めない（計画用）
- 日次生成は当日変更を反映
- README は Phase 1 記載のまま（本ドキュメントを参照）

### Phase 4 追加

- 振り返りメモ（`review_note`）は保存のみ — 画面再訪時に再表示されない
- 小規模リスケは 1 ブロックにつき最初に見つかった空き日へ 1 件配置（同一日に複数まとめない）
- 大規模リスケ承認は `goal_budgets.allocated_minutes` の上書きのみ
- 大規模リスケ: **3 回/日**（目標分解は 5 回/日）

### Edge Function デプロイ

- **`Failed to bundle … date-fns`** → core の scheduling モジュールに npm 依存を入れない（または Deno 用 import map が必要）
- **`Failed to bundle … zod`** → 非 AI 関数で `dist/index.js` を import していないか確認
- AI 関数を変更したら **`goal-decompose` / `reschedule-major` を再 deploy**（`call-ai.ts` は `_shared` 経由で共有）
