## 6. Phase 1 で実装済みの機能

### 認証

- メール + パスワード（Supabase Auth）
- 新規登録時に `profiles` / `user_preferences` を自動作成（DB トリガー）

### オンボーディング

- 平日/休日の起床・就寝時間
- 1 回あたりの作業可能時間

### 基本設定（`/settings/preferences`）

- 起床・就寝・集中時間帯・作業上限

### 生活リズム（`/settings/routines`）

- CRUD（朝食/昼食/夕食/風呂/休憩/その他）
- 「20:00 ごろ」→ `preferredTime` + ±許容幅（`earliestTime` / `latestTime`）へ自動変換

### 固定予定（`/settings/fixed`）

- CRUD（曜日・移動時間対応）
- 空き時間計算時に必ず除外
- **`commute_minutes` は終了時刻の後のみ**ブロック（行きの移動は Phase 1 未対応。往復は別固定予定または開始時刻を早める workaround）

### ホーム（`/`）

- 今日の生活予定一覧
- 空き時間スロット表示
- ブロック中の予定表示
- **今日だけ変更**（起床/就寝/生活リズムの skip・時間変更 → 空き時間再計算）

## 9. コアロジック（`packages/core`）

### 空き時間計算

```
packages/core/src/scheduling/
├── constants.ts       # 定数・ROUTINE_TYPE_LABELS
├── time-utils.ts      # 時刻変換、「ごろ」→ 許容幅
├── overrides.ts       # 当日変更の反映
├── block-builders.ts  # 固定予定・生活リズムのブロック構築
├── formatters.ts      # 表示用フォーマット
└── free-time.ts       # calculateFreeTime（オーケストレータ）
```

**処理順序**

1. 起床〜就寝の範囲を確定（当日変更反映）
2. 固定予定をハードブロック
3. 生活リズムをブロック（preferredTime + duration）
4. 残りを空き時間スロットとして返却

### DB → ドメイン変換

`packages/core/src/mappers/schedule-input.ts`

- `buildScheduleDataSnapshot()` — Supabase 取得データを `calculateFreeTime` 入力に変換
- UI 層でのマッピング重複を避けるため、**新 Phase でも mapper を更新する**

### バリデーション（Zod）

`packages/core/src/schemas/` — フォーム入力・AI 出力検証用（Phase 2 から本格利用）

### テスト

```bash
pnpm --filter @ai-scheduler/core test
```

- `tests/time-utils.test.ts` — 「ごろ」変換
- `tests/free-time.test.ts` — 空き時間計算、当日変更

## 13. 既知の技術的判断・注意点

### `database-types.ts` の命名

- 旧名 `database.types.ts` は IDE が `./database.types.js` を解決できずエラーになった
- **`database-types.ts`（ハイフン）を使用**すること
- `index.ts` からは `export type { Database, Json, Tables }` で型のみ export

### 「ごろ」の許容幅

- 実装: 希望時刻を中心に **±N 分（デフォルト 30 分）** で `earliestTime` / `latestTime` を算出
- 企画書例（20:00 → latest 21:00）は非対称だが、実装は対称 ±30 分（latest = 20:30）

### 当日変更の skip（起床/就寝）

- DB・UI 上は skip 可能だが、空き時間計算では **modify のみ反映**（skip は未対応コメントあり）

### 当日変更の `target_date`

- アプリは **ブラウザのローカル日付**（`YYYY-MM-DD`）で保存する
- Supabase SQL Editor の `CURRENT_DATE` は **UTC** のため、日本時間の「今日」とずれることがある
- 調査時は日付条件なしで全件取得するか、`(now() AT TIME ZONE 'Asia/Tokyo')::date` を使う（[`テーブル設計_Phase1.md`](./テーブル設計_Phase1.md) §9 参照）

### オンボーディング遷移（2026-05-23 修正済み）

- **症状**: 保存 API は 204 成功だが生活リズム画面に進めない／画面がちらついて「読み込み中」で止まる
- **原因**: `invalidateQueries` 直後の `navigate` と `AppLayout` の古いキャッシュによる `/onboarding` ↔ `/settings/routines` ループ
- **対策**: 保存後は `refetchQueries` ではなく **`setQueryData` でキャッシュを即更新**。設定済みユーザーは `<Navigate>` でスキップ
- **完了判定**: `wake_time_weekday` と `sleep_time_weekday` の両方が非 NULL

### 休日就寝時刻のデフォルト

- 旧デフォルト `24:00` は HTML `type="time"` 非対応で表示が消える／DB では `00:00` に変換される
- 現在のデフォルトは **`23:00`**

### 固定予定の移動時間

- `commute_minutes` は **`end_time` の直後**にのみブロックを追加（`block-builders.ts`）
- 通勤往復（行き30分＋帰り30分）を1フィールドで表現する機能は Phase 1 にない

### `.gitignore`

- 2026-05-23 更新: `.pnpm-store/`, `*.tsbuildinfo`, `.vite/`, `.idea/` 等
- **`apps/web/.env` はコミットしない**（`git add .` でも gitignore により除外される）

### CI

- `.github/workflows/ci.yml` — core の build + test + web typecheck
- RLS 自動チェック（plain Postgres）は auth スキーマ依存のため未実装。オンラインは `supabase db push` または Dashboard で検証

### ビルド成果物

- `packages/core/dist/` に旧 `database.types.*` が残っている場合がある → `pnpm --filter @ai-scheduler/core build` で再生成
